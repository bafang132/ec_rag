# 跨境电商 RAG 智能问答系统 · 技术文档

> 版本：v1.0.0 ｜ 项目根：`ec_rag/` ｜ 服务端口：**8000 导入服务**、**8001 查询/管理/测评服务**

---

## 1. 项目概述

本系统基于成熟的分层 RAG 架构与 LangGraph 编排范式，结合本地向量库与 C 语言加速实践，构建的**生产级跨境电商知识库智能问答系统**。

两条相互独立的 LangGraph 链路：

- **导入链路（Import）**：文件 → Markdown（格式归一化）→ 图片处理 → 标题语义切分 → 元数据抽取 → 混合向量化 → 写入向量库。
- **问答链路（Query）**：用户问题 → 意图识别/查询改写/领域筛选 → 混合向量检索（dense + 稀疏）→ RRF 融合 → Reranker 重排 → 按角色模板生成答案（引用溯源 + 合规提醒）。

**多后端自动降级**是贯穿全系统的设计原则：任何外部依赖（Milvus / BGE-M3 / bge-reranker / MongoDB / MinIO / MinerU / LLM API）缺失时，系统自动切换到可用的下一级实现，保证开箱即用。

## 2. 技术栈总览

| 类别 | 技术 | 说明 |
|---|---|---|
| Web 框架 | FastAPI + Uvicorn | 8000 导入服务 / 8001 查询服务 |
| 图编排 | LangGraph（StateGraph） | 导入 / 问答两条多节点工作流 |
| LLM | OpenAI 兼容协议 | LangChain ChatOpenAI（装了就用）⇄ 原生 openai SDK 客户端；支持 DashScope/智谱/DeepSeek |
| Embedding | BGE-M3（FlagEmbedding） | dense(1024) + sparse 混合向量 |
| Embedding 备用 | 智谱 embedding-2 API / 哈希向量 | 逐级降级（auto 模式） |
| Reranker | BAAI/bge-reranker-large（FlagReranker） | Cross-Encoder 精确重排 |
| Reranker 备用 | LLM 批量打分 | 本地模型不可用时保证链路完整 |
| 向量库 | Milvus（pymilvus） | 稠密 + 稀疏混合检索（RRF） |
| 向量库备用 | 本地 numpy 向量库 | dense 余弦 + BM25 关键词，零依赖开箱即用 |
| PDF 解析 | MinerU 云端 API | 版面/表格/公式还原 |
| PDF 备用 | pypdf 本地提取 | 保留页码信息供引用 |
| 文档转换 | markitdown | docx/html/xlsx/pptx/epub → Markdown |
| 对象存储 | MinIO | 文档图片（可选） |
| 持久化 | MongoDB ⇄ 本地 JSON | 会话元信息 + 聊天记录 |
| 底层加速 | C 语言（ctypes） | 文本分块 + 余弦相似度，**加载自检失败自动降级** |
| 日志 | loguru ⇄ 标准库 logging | 控制台 + 文件双输出 |
| 测试 | pytest | 89 用例（检索/生成/导入/稳定性/性能） |

## 5. 导入链路详解

图入口 `app/process/import_/agent/main_graph.py`，状态 `ImportGraphState`。

```
node_entry ──条件路由──> node_pdf_to_md ──> node_md_img ──> node_document_split
                     ├─> node_doc_to_md ──> node_md_img ──> node_document_split
                     └─> node_md_img（Markdown 直读，md_path 在入口登记）
node_document_split → node_metadata_extract → node_embedding → node_index → END
```

| 节点 | 作用 | 关键实现 |
|---|---|---|
| `node_entry` | 文件类型识别与路由 | `classify_file` 五分法：markdown/pdf/plain_text/convertible/legacy_binary/unsupported |
| `node_pdf_to_md` | PDF → Markdown | MinerU 优先（含 >200 页本地拆分合并），pypdf 兜底 |
| `node_doc_to_md` | 可转换格式 → Markdown | markitdown；纯文本走编码探测链（utf-8-sig→gbk→gb18030→big5→latin-1） |
| `node_md_img` | 图片处理 | 扫描被引用图片 →（可选 VL 摘要）→ 上传 MinIO/本地静态 → 修复引用（alt 替换为摘要） |
| `node_document_split` | 语义切分 | 标题粗切 → 超长 C 加速切分 → 过短按同父标题合并 |
| `node_metadata_extract` | 元数据抽取 | LLM 抽取 + 关键词规则兜底（**文件名优先匹配 + 加权词频计分**） |
| `node_embedding` | 混合向量化 | 语义增强文本（平台/市场/类目 + 术语归一化）+ 分批 60 条 |
| `node_index` | 入库 | 门面写入；同主体先删后插保证覆盖更新 |

**领域元数据 Schema**：`item_name`（主体）、`platform`（平台）、`market`（市场）、`category`（类目）、`doc_type`（文档类型）、`article_title`、`author`、`source_file/path`。

## 6. 问答链路详解

图入口 `app/process/query/agent/main_graph.py`，状态 `QueryGraphState`。

```
node_ec_intent ──(寒暄/澄清已产出答案)──> node_answer_output
              └─(需检索)──> node_search → node_rrf → node_rerank → node_answer_output → END
```

| 节点 | 作用 | 关键实现 |
|---|---|---|
| `node_ec_intent` | 意图识别 + 查询改写 + 领域筛选 + 合规风险 | 单次 LLM 调用完成改写/抽取；寒暄前置检测直达答案；规则兜底保证 LLM 不可用时不中断 |
| `node_search` | 混合检索 | 语义增强查询（改写 + 平台/市场/类目标签 + 术语归一化）；dense + BM25/稀疏两路；可选联网搜索并发 |
| `node_rrf` | RRF 融合 | 语义路 + HyDE 路等权融合（k=60） |
| `node_rerank` | 精确重排 | Cross-Encoder/LLM 打分 → 按相邻分差动态截断 TopK（min 5 / max 10）→ LRU 缓存 |
| `node_answer_output` | 答案生成 | 三角色模板 + 合规提醒注入 + 引用来源 + SSE 流式 + 历史落库 |

### 6.1 软召回策略（重要设计决策）

平台/市场/类目标签**不做标量硬过滤**，仅拼接到查询文本做语义增强。原因（实测教训）：LLM 抽取的标签值常与索引标签不匹配（如抽成「北美」而索引写「美国」），硬过滤会把正确文档整批排除，导致召回崩溃。精度交由下游重排器负责。如需开启：`RETRIEVAL_USE_SCALAR_FILTER=true`。

### 6.2 合规风险雷达

`ec_config.COMPLIANCE_RISK_RULES` 定义五类高风险规则（账号封禁/知识产权/税务合规/禁售品/平台处罚），命中后：
- 意图节点记录 `risk_level`（medium/high）与提醒文案；
- 答案生成时把合规提醒拼入上下文，seller/operator 模板强化【风险提示】栏目；
- 测评模块的 safety 维度对「引导违规操作」一票否决（F 级）。

### 6.3 三角色回答模板

| 角色 | 模板 | 结构 |
|---|---|---|
| seller 新手卖家 | `seller_answer_out` | 结论 → 操作步骤 → 注意事项 → 风险提示 → 参考来源 |
| operator 成熟运营 | `operator_answer_out` | 策略结论 → 执行方案 → 数据与指标 → 风险与合规 → 参考来源 |
| expert 风控专家 | `expert_answer_out` | 专业结论（含置信度）→ 依据分析（矛盾/时效）→ 合规审查（风险分级）→ 建议动作 → 参考来源 |

## 7. 向量库双后端

### 7.1 本地 numpy 向量库（默认，零依赖）

`app/infra/vectorstore/local_store.py`：

- 持久化：`vectors.npy`（(N, dim) float32）+ `meta.json`（切片元数据）。
- 检索：dense 余弦（numpy 矩阵乘）+ BM25 关键词（k1=1.5, b=0.75），两路 min-max 归一化后按 0.9/0.1 加权（策略与 Milvus 加权 ranker 一致）。
- 管理：`list_items`（按 item_name 聚合）、`query_all`（条件查询）、`delete_by_item/id`。
- 健壮性：元数据/向量文件损坏或维度不一致时自动重置为空库；并发读写持 RLock。
- 损坏自恢复与持久化往返有专项测试覆盖。

### 7.2 Milvus（生产）

`app/infra/vectorstore/milvus_store.py` + `app/shared/clients/milvus_utils.py`：

- 集合 schema 与本地库字段对齐（含跨境电商元数据字段），dense IP 索引 + sparse 倒排索引。
- 混合检索经 `AnnSearchRequest` 两路 + `RRFRanker` 融合。
- `ensure_loaded` 带进程内缓存，避免每次检索多一次控制面 RPC。

## 8. C 语言加速（带自检的安全设计）

`app/shared/utils/c_accel.py` + `csrc/`：

- **文本分块**：`csrc/text_splitter.c`（按中文标点优先级递归切分）。
- **余弦相似度**：`csrc/similarity.c`（电商加权 1.2 倍，保序；`EC_SIM_WEIGHT` 可校正）。
- **加载自检**：DLL 加载后立即用固定用例（前导空白/多段落/无分隔符）验证分块数量、内容与 free 流程；自检不通过则**禁用 C 路径并降级纯 Python**，杜绝脏 DLL 拖垮服务。
- **源码修复**：原跨境电商项目的 `trim()` 返回栈内偏移指针后被 `free()`，文本含前导空白时构成堆损坏（实测其预编译 DLL 直接崩溃）；本仓库 `csrc/text_splitter.c` 已修复（memmove 回起始地址）。
- 编译：`csrc/build.bat`（MinGW）或 `csrc/build.sh`（gcc），产物放 `csrc/prebuilt/`。

## 9. 专业测评模块

`evaluation/`（测评体系适配跨境电商场景）：

- **三种模式**：`offline`（进程内调 query_app 图，检索+生成全套）/ `online`（HTTP /query，仅生成）/ `selftest`（合成数据，零依赖自检）。
- **指标**：检索 HitRate@k/Recall@k/Precision@k/MRR/NDCG@k；生成忠实度/相关性/上下文/完整性/**合规安全性**；客观子分（要点覆盖率 + 参考答案 F1）。
- **综合评分**：`0.40 × 检索 + 0.60 × 生成`；safety ≤ 0.4 强制 F 级（一票否决）。
- **基线对比**：`--compare` 同时跑纯 LLM 基线，量化 RAG 增量价值。
- **测试集**：`evaluation/testset/ec_eval.jsonl` 20 条，金标准对应 14 篇示例文档，含 9 条合规红线用例。
- CLI：`python -m evaluation.run_eval --mode offline --use-llm`；网页：`http://localhost:8001/eval/html`。

## 11. 端到端数据流

**导入**：`上传(8000) → node_entry → [PDF]MinerU/pypdf → node_md_img → node_document_split(标题粗切+C切分) → node_metadata_extract(LLM+规则兜底) → node_embedding(语义增强+术语归一化+分批) → node_index(门面写入)`

**问答**：`提问(chat.html,8001) → /query(SSE) → node_ec_intent(改写+筛选+合规) → node_search(混合检索+可选联网) → node_rrf → node_rerank(动态TopK) → node_answer_output(角色模板+引用+流式) → MongoDB/JSON 落库`

## 13. 已知实现注意事项

1. 完整 LangGraph 链路需 `pip install -r requirements.txt`；未装 langgraph 时仅图编排层不可用，其余模块（配置/工具/测评/本地库）仍可独立导入。
2. BGE-M3 / bge-reranker 首次使用会自动下载模型（或配置 `BGE_M3_PATH` / `BGE_RERANKER_LARGE` 指向本地路径）；CPU 环境务必 `BGE_DEVICE=cpu` + `BGE_FP16=0`。
3. MinerU 单文件 ≤200 页，超大 PDF 自动本地拆分逐片解析后合并。
4. 本地向量库为单进程设计（RLock 保证进程内并发安全）；多 worker 部署请使用 Milvus。
5. C 加速库需自行编译（见第 8 节）；未编译时全功能走纯 Python，仅分块/相似度性能下降。
6. 管理接口无鉴权（演示系统）；生产部署请在网关层加固。
